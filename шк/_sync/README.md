# GP Classroom Live Sync

Это дополнительный модуль для двух уже опубликованных страниц:

- `/шк/res-6-1-2627/` — посещаемость и оценки.
- `/шк/поездка-1026/` — участники поездки, распределение по квестам, автобус.

**Никакие исходные списки, оценки и зашифрованные JSON не изменяются.**

## Как устроено

GitHub Pages показывает интерфейс. Существующий localStorage остаётся локальным
кэшем. Supabase PostgreSQL хранит версии состояния с ограничением
`owner_id = auth.uid()` (RLS). Однократная авторизация Google сохраняет сессию
на устройстве. Изменения в других открытых вкладках/на другом устройстве
передаются Supabase Realtime и обновляют страницу.

## Подключение

1. Создать проект Supabase, включить Google OAuth в Authentication.
2. Запустить `schema.sql` в SQL Editor. Включить таблицу
   `gp_classroom_sync` в публикации `supabase_realtime`.
3. В `config.js` вписать Project URL и **publishable key**, но НИКОГДА
   не `service_role`, secret key или токены OAuth.
4. Открыть страницу на устройстве, где исходные данные уже доступны,
   один раз войти через Google. Там создастся первая запись в облаке.
5. На другом устройстве войти тем же аккаунтом Google. Состояние загрузится
   автоматически. Дальше обновления передаются без ручных кодов.

Если поля в `config.js` пустые, существующие страницы работают как прежде
без запросов к облачному сервису.

## Ограничения и безопасность

- GitHub Pages — публичный статический сайт. В самом репозитории остаются
  только зашифрованные исходные файлы. Ключей расшифровки в коде нет.
- Снимки состояния в Supabase содержат фактические данные, поэтому нельзя
  открывать таблицу для роли `anon`. RLS/Google Auth обязательны.
- Это первая версия для **одного владельца** на нескольких устройствах.
  Одновременное редактирование одного поля с двух устройств может создать
  конфликт. Модуль сообщает о нём и не перезаписывает локальную работу.
  Для совместного редактирования несколькими педагогами нужна событийная модель
  с правами участников и отдельными ревизиями строк.
- Перед первой синхронизацией скачайте резервный JSON.
- При первом заходе с нового устройства исходная страница может показать
  сообщение об отсутствии данных до входа Google и получения облачного снимка.

## Размещение

Эти файлы должны оставаться в `шк/_sync/`.
Обе HTML-страницы подключают `config.js` и `live-sync.js` после своих
существующих скриптов.
