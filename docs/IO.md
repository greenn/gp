# IO — правила публикации из ChatGPT

Назначение: команда **GP `@gp io`** превращает один текущий результат (текст, исследование, упражнение, визуализацию) в публичную автономную страницу на GitHub Pages.

## Синтаксис

| Команда | Расположение | Что публикуется |
|---|---|---|
| `@gp io` | `s/<slug>/` | Текущий результат, читабельная HTML-страница |
| `@gp io ds` | `ds/<slug>/` | Исследование, интерактивная HTML-реализация |
| `@gp io ds ?url` | `ds/<slug>/` | То же; дополнительно подчёркивает запрос ссылки, которая и так обязательна |

`?url` не адрес источника и не имя папки. Оно не требуется для автоматического URL.

## Slug

Короткий и понятный английский `kebab-case`: `ai-assessment-tools`, `energy-consumption-guide`. Только латиница `a-z`, цифры и дефисы. Без пробелов, `..`, служебных URL-символов. Дата в конце `-YYYY-MM-DD` — для материалов, привязанных к конкретной дате или версии, в остальных случаях опциональна. Коллизии решать выбором нового предметного slug или суффиксом `-2`.

## Структура

```text
s/topic-name/
  index.html
  source.md               # если доступен текст результата
  assets/...              # если нужны локальные файлы

ds/research-topic/
  index.html
  source.md               # по возможности полный проверенный текст
  data/...                # таблицы/графики/JSON при наличии
  assets/...
```

HTML автономный: без обязательной сборки или сервера. Мобильная адаптация, семантика, UTF-8, таблицы с прокруткой, поддержка клавиатуры. Содержание видно и при отключённом JS, интерактив дополняет его. Только относительные пути на собственные файлы. В исследованиях полезны навигация по разделам, поиск, фильтры таблиц, раскрываемые пояснения и просмотр источников. Нельзя выдумывать отсутствующие данные или ссылки.

## Процедура

1. Найти конкретный результат в текущем чате, убедиться в доступности байтов приложенных файлов.
2. Прочитать [AGENTS.md](../AGENTS.md), проверить права записи в `greenn/gp`, текущее дерево, корневой `index.html`, `README.md`.
3. Подготовить папку публикации. Не копировать чувствительные персональные материалы, токены, приватные ссылки, закрытые данные и чужой защищённый текст без разрешения.
4. Проверить HTML, скрипты, JSON, ссылки и доступность изображений. Не использовать `sandbox:/`, локальные абсолютные пути и временные URL.
5. Атомарно записать в `main`: каталог публикации, карточку в корневом `index.html`, новую запись в разделе «Публикации» корневого `README.md`.
6. Проверить SHA коммита и файлы. Адрес зависит от активного корневого `CNAME`: при домене `gp.nadube.ru` в опубликованной ветке — `https://gp.nadube.ru/<category>/<slug>/`, до подключения домена — `https://greenn.github.io/gp/<category>/<slug>/`. Не заявлять, что GitHub Pages уже обновился, без проверки публичного ответа сайта.

**Важно:** `greenn/gp` — публичный репозиторий публикаций. `greenn/gpp` — приватный репозиторий исходников плагинов. Команда `@gp io` работает с GitHub, а `@gp drive` — с Google Drive; не объединять эти сценарии без явной просьбы пользователя.
