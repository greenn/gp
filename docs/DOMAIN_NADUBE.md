# Домен gp.nadube.ru для GitHub Pages

> **Статус:** подготовлено; **не активировать**, пока не готова DNS-запись и не выполнена проверка. Эта конфигурация находится в отдельной ветке/черновом PR и не влияет на текущий сайт.

## Цель и границы изменений

- Публичный репозиторий: `greenn/gp`; публикация GitHub Pages из корня ветки `main`.
- Новый адрес **после активации**: https://gp.nadube.ru/.
- Пример: https://gp.nadube.ru/wd/1020-sports-ranking/.
- Прежний адрес: https://greenn.github.io/gp/ (после включения GitHub Pages обычно перенаправляется на новый домен).
- **Не менять** `nadube.ru`, `www.nadube.ru`, `brusina.nadube.ru`, корневые NS-записи и A/AAAA домена. Обслуживание действующих сайтов должно остаться прежним.

## DNS — единственное действие вне GitHub

DNS-зону нужно редактировать **у фактического DNS-провайдера** (в панели REG.RU только если NS действительно обслуживаются там). Для новой записи:

| Поле | Значение |
|---|---|
| Тип | `CNAME` |
| Имя / Host | `gp` |
| Значение / Target | `greenn.github.io` |
| TTL | автоматический или 300 секунд |

Полная запись: `gp.nadube.ru. IN CNAME greenn.github.io.`.

**Важно:** значение — именно `greenn.github.io`, **не** `greenn.github.io/gp` и не HTTP/HTTPS URL. Если для имени `gp` уже существуют A/AAAA/CNAME, не удаляйте их, пока не убедитесь, что поддомен не занят другим сайтом. CNAME не может сосуществовать с другими записями того же имени.

### Дополнительная защита домена (рекомендовано)

В профиле GitHub аккаунта `greenn`: **Settings → Pages → Add a domain** → `nadube.ru`. GitHub покажет точное значение TXT; добавьте предложенную TXT-запись в DNS и завершите **Verify**. Значение токена заранее неизвестно — его нельзя придумывать. Проверка защищает поддомены от перехвата.

## Безопасная активация

1. Убедитесь, что `gp.nadube.ru` свободен и выбранный DNS-провайдер действительно обслуживает записи `nadube.ru`.
2. Подготовьте проверку владения доменом (TXT, если выполняете её) и DNS CNAME, не меняя остальные записи.
3. Когда готовы выполнить DNS-изменение, переведите PR `config/gp-nadube-pages` в `main`: он добавляет корневой `CNAME` со значением `gp.nadube.ru`. Не переименовывайте его, это специальный файл GitHub Pages.
4. Добавьте/включите запись DNS `gp → greenn.github.io` в тот же период. При публикации из ветки GitHub автоматически читает корневой `CNAME`; дополнительно откройте **greenn/gp → Settings → Pages → Custom domain** и проверьте, что там указан `gp.nadube.ru`. При необходимости сохраните его вручную.
5. Проверьте DNS и публичный доступ, затем включите **Enforce HTTPS** в Settings → Pages, когда эта опция станет активной. Выпуск сертификата и распространение DNS могут занять до 24 часов.
6. Убедитесь, что все ссылки работают без префикса `/gp/` на новом домене, и что `nadube.ru` и `brusina.nadube.ru` доступны по-прежнему.

### Проверки (Windows PowerShell)

```powershell
Resolve-DnsName gp.nadube.ru -Type CNAME
curl.exe -I https://gp.nadube.ru/
curl.exe -I https://gp.nadube.ru/wd/1020-sports-ranking/
curl.exe -I https://greenn.github.io/gp/
```

Ожидается DNS CNAME на `greenn.github.io`, корректная публикация каталога и редирект со старого адреса (при завершённой настройке). Ключевой критерий — успешный HTTPS-ответ и загруженные изображения/скрипты.

## Откат

Если после активации проблема: уберите новый CNAME DNS для `gp` и в настройках GitHub Pages удалите кастомный домен (или уберите корневой файл `CNAME` коммитом, если GitHub Pages использует ветку). Восстановите прежний GitHub Pages URL, проверьте доступность. Не трогайте другие DNS-записи домена.
