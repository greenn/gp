ingest-vn-catalog

Импорт визуальных новелл в каталог gmx: скриншоты, диалоги, сохранения и сведения об игре.

Постоянное хранилище: логический путь src/<slug> соответствует S:\dvb\gmx\<slug> на внешнем SSD. Если диск или каталог недоступен, остановиться; замену в проекте не создавать. База и инструменты остаются в J:\dv\gmx.

Когда и как запускать

Передайте папку одной игры или wrapper — папку с несколькими играми. Режим auto определяет тип автоматически; его можно задать явно.

python J:/dv/gmx/tools/ingest_vn.py "PATH"
python J:/dv/gmx/tools/ingest_vn.py "PATH" --mode game
python J:/dv/gmx/tools/ingest_vn.py "PATH" --mode wrapper
python J:/dv/gmx/tools/ingest_vn.py "PATH" --copy-more
python J:/dv/gmx/tools/ingest_vn.py "PATH" --delete-source
python J:/dv/gmx/tools/ingest_vn.py "PATH" --sync
Удаление источника: --delete-source применяют только по явной просьбе пользователя. Он включает --copy-more и удаляет переданную папку целиком только после успешной обработки всех игр. Если удаление планируется позже, при первом импорте используют --copy-more.

Новые скриншоты после игры

--sync предназначен для уже внесённых в каталог игр: он перемещает только новые скриншоты и логи, не копирует сохранения, не изменяет more и не удаляет источник. Можно указать одну игру или wrapper; игры, отсутствующие в базе, пропускаются.

/ingest-vn-catalog --sync D:\gmx
/ingest-vn-catalog --sync "C:\_\gmx\Away From Home"

Что происходит с файлами

ИсточникДействие и назначение
screenshots / screenshotПереместить в src/<slug>/screenshots.
Папка = — AI-фотоПереместить в src/<slug>/ai.
Логи диалоговПереместить в src/<slug>/logs; технический log.txt двигателя не относится к ним.
Сохранения игры и AppDataКопировать в src/<slug>/saves/; оригиналы не перемещать.

Исполняемые файлы и ресурсы игрыОставить в источнике до явно запрошенного удаления.

В дампе остатков scr и обычные изображения игры относятся к скриншотам, прочие файлы — к more, а = — к ai. Если пользователь обозначил весь дамп как AI-фото, все изображения, включая вложенные, направляются в ai. Неясные случаи пропускаются.

Название, версия и разработчик

  • Slug — kebab-case, не более 32 символов.
  • Версия определяется по приоритету: _version в сохранении, config.version, версия в log.txt, затем имя папки. Несколько версий сохранений записываются в базу.
  • Разработчик ищется в gui.about, CompanyName исполняемого файла, затем в интернете по названию и версии; DefaultCompany игнорируется.
  • Время игры берётся только из _game_runtime сохранений или остаётся пустым.

После запуска

  1. Прочитать отчёт J:\dv\gmx\db\last_ingest.json.
  2. При NEED_WEB_DEVELOPER найти разработчика и обновить базу.
  3. Сообщить slug, версию, состав перенесённых и скопированных файлов, даты и результат синхронизации.
  4. Если пользователь просил удаление, выполнять его только после успешной обработки.
