YOUR DEVELOPMENT WORKFLOW · D / 0.1.1

От идеи —
к работающему коду.

D превращает обычное описание задачи, скриншот интерфейса или ошибку в точный запрос для coding agent.

Не заставляет сильные модели повторять подробный алгоритм. Вместо этого фиксирует результат, контекст, ограничения, самостоятельность и проверку. Учитывает среду Codex, Cursor, Claude Code и Grok.

Что такое D. Инструкционный плагин внутри ChatGPT. По умолчанию пишет промпт, а не изменяет код. Для фактической разработки нужна явная команда @D build и доступ к нужным инструментам.

01 / начать за минуту

Начни с результата.

Выбери нужный сценарий. Скопируй команду и отправь в ChatGPT с подключённым D.

@D Добавь экспорт JSON в текущий проект

Один промпт для Codex по умолчанию.

@D cursor Исправь мобильное меню

Промпт под среду Cursor.

@D ui cursor Сделай приложение по изображению

Превращает прикреплённый референс в техническую задачу.

@D plan claude Спроектируй приложение

Подробный план с критериями готовности, но без изменения кода.

02 / каталог команд

Выбирай намерение, а не сценарий исполнения.

Команда указывает, что нужно получить. Платформа уточняет, под какую среду формируется результат.

Команды доступны ниже

@D [задача]

Готовый короткий промпт. Цель по умолчанию — Codex.

@D prompt cursor [задача]

Промпт с учётом выбранной среды.

@D cursor [задача]

То же, что «@D prompt cursor».

@D cursor grok [задача]

Cursor — harness, Grok — выбранная модель.

@D cursor claude [задача]

Cursor с моделью Claude, если она доступна.

@D plan [задача]

Полный план, этапы, риски, критерии приёмки.

@D plan claude [задача]

План с учётом работы Claude Code.

@D ui [платформа] [задача]

Скриншот → промпт на функциональный интерфейс.

@D ui plan cursor [задача]

Подробный план экранов, данных и переходов.

@D ui build [задача]

Прямая реализация с доступными инструментами.

@D build [задача]

Выполнение, когда есть доступ к проекту.

@D fix [платформа] [ошибка]

Задача на поиск первопричины и регрессионную проверку.

@D rules [платформа] [проект]

Проектные правила для выбранного harness.

@D audit [промпт]

Сокращение и усиление постановки задачи.

@D check [результат]

Проверка доступных результатов и пробелов.

@D help

Краткая справка внутри ChatGPT.

↗
Порядок допускает обе формы: @D ui cursor ... и @D cursor ui .... Название инструмента может быть и в обычной фразе: «составь промпт для Cursor».

03 / адаптеры

Одна задача. Разные среды.

D не пишет четыре длинных варианта. Он сохраняет смысл задачи и корректирует только полезные детали целевого harness.

⌘OpenAI / CODEX

Codex

Результат, ограничения, критерии готовности. Агент самостоятельно изучает релевантный код и выбирает реализацию. Файл правил — AGENTS.md, если используется в проекте.

Не навязывать обязательный большой план и субагентов.
▣IDE / CURSOR

Cursor

Контекст открытого проекта, существующие компоненты, референс. При доступности Browser — визуальная проверка адаптивности. Проектные правила — .cursor/rules/*.mdc или поддерживаемый AGENTS.md.

Cursor — среда, а не одна модель.
◇ANTHROPIC / CODE

Claude Code

Точный контекст, буквальные логи, осторожность с неизвестным API. CLAUDE.md — стабильные соглашения; Plan Mode полезен для сложных задач, но не обязателен.

Не требовать бесконечных повторных проверок.
✦XAI / GROK

Grok / Grok Build

Конкретный результат, границы, проверка. Отличать модель Grok от среды Grok Build: сама модель не гарантирует доступа к файлам, терминалу или браузеру.

Не придумывать специальные обязательные ключевые слова.

Среда + модель

Для команды @D cursor grok главными остаются контекст, правила и инструменты Cursor. Grok — только выбранная модель. Аналогично работает @D cursor claude. Наличие модели в конкретной установке не гарантировано.

Пример: Cursor с Grok
@D cursor grok Добавь фильтр по этажности в каталог.
Не меняй базу и существующий дизайн.

04 / главное применение

Сгенерировал UI? Теперь сделай его рабочим.

Плоское изображение задаёт внешний вид, но не определяет API, данные и поведение. D помогает описать то, чего не хватает для реализации.

ВИДНО НА РЕФЕРЕНСЕ
  • Композиция и расположение блоков
  • Цвета, шрифты, иерархия
  • Подписи и видимые контролы
  • Примерные пропорции
НУЖНО ОПРЕДЕЛИТЬ
  • Поведение кнопок и переключателей
  • Состояния и навигацию
  • Откуда берутся данные
  • Проверку desktop и mobile
Готовая команда для Cursor
@D ui cursor Создай рабочее приложение по
приложенному изображению. Сохрани композицию
и стиль. Все видимые элементы должны работать.

Что получит внешний coding agent

Точное описание референса, работающие компоненты вместо скриншота-подложки, осмысленные состояния элементов, ограничения по текущему проекту и способ проверки. Для больших интерфейсов есть @D ui plan.

!
Изображение из ChatGPT не переносится автоматически в Cursor или Codex. После получения промпта приложи тот же макет непосредственно в целевом инструменте. Не требуй вымышленного пути к файлу.

05 / проектирование и выполнение

Plan, Prompt и Build — разные действия.

01

PROMPT · постановка задачи

Один готовый текст для внешнего агента. Быстрое делегирование без подробного микроменеджмента.

02

PLAN · полный план

Цель и MVP, экраны, данные, ограничения, проверяемые этапы, тесты, риски и короткий handoff-промпт. Код не изменяется.

03

BUILD · реализация

D пытается изменить код доступными в чате средствами. Не подключается к запущенному Cursor/Claude Code сам по себе. Не делает деплой и опасные изменения без полномочий.

04

FIX / CHECK · исправление и проверка

Fix формирует промпт на поиск первопричины ошибки. Check оценивает только фактически доступные результаты — не выдаёт непроведённые тесты за успешные.

План для Claude Code
@D plan claude Спроектируй локальное приложение
для школьной интерактивной доски без сервера

Файлы правил описывают соглашения проекта. Не стоит вставлять в них весь текущий план разработки.

08 / вопросы и ответы

Частые вопросы.

Нужно ли для Codex писать очень подробный промпт?

Обычно нет. Для обычной задачи достаточно цели, значимых ограничений и проверки. Детализация нужна для сложных правил, интеграций и точных требований.

Чем отличается «@D cursor» от «@D prompt cursor»?

Это две равнозначные формы. Вторая явно указывает режим prompt. Оба варианта формируют промпт для Cursor.

Что значит «@D cursor grok»?

Целевая среда — Cursor, модель — Grok. Плагин использует особенности среды как основной контекст. Доступность конкретной модели в Cursor требуется проверить отдельно.

Может ли D сам открыть Cursor и запустить код?

Нет, не только по названию среды. D может работать с кодом через реальные инструменты данного чата, если они подключены и действие разрешено. Иначе выдаст промпт для внешнего агента.

Почему кнопки на картинке не равны работающему приложению?

Референс показывает только внешний вид. Поведение кнопок, хранение данных и связи с сервером нужно определить отдельно. D предлагает минимальные рабочие состояния без фиктивного API.

Если назвать Cursor в обычной фразе, D учтёт это?

Да, когда Cursor явно назван целевой средой: например, «составь промпт для Cursor». Если Cursor является объектом разработки, автоматического переключения не будет.

Сохраняется ли выбор инструмента между чатами?

Нет. Выбор действует для текущей задачи. По умолчанию используется Codex.

Как выбрать между prompt, plan и build?

Prompt — передать задачу coding agent. Plan — спроектировать этапы. Build — пытаться реализовать прямо сейчас через доступные инструменты.
