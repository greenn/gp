YOUR HOME FOR RESULTS · СПРАВКА GP

Все результаты —
в одном движении.

GP помогает собирать изображения, сохранять материалы в Google Drive, архивировать переписку, создавать вкладки в Google Документах и публиковать интерактивные страницы на GitHub Pages.

Это набор команд внутри ChatGPT. Вы даёте короткую инструкцию через @gp, а GP выбирает нужный рабочий процесс и доступные инструменты. Никаких серверов, сложных настроек или отдельной панели управления.

Смотреть все команды ↓Собрать команду →
✳
Как начать. Выберите команду ниже, нажмите «Копировать» и вставьте её в беседу с подключённым GP. Примеры не запускают действия на этой справочной странице.

01 / визуальные результаты

VNS. Галерея с памятью о сборках.

Из результатов генерации — в упорядоченный архив: каждая доступная картинка сопровождается подробным промптом и структурированным описанием.

@gp vns

Полная сборка всех доступных изображений, созданных GPT в текущем чате.

@gp vns next

Только изображения, которых не было в предыдущих подтверждённых сборках.

@gp vns drive

ZIP в чате и загрузка набора в Google Drive: gp/vns/MMDD-N.

@gp vns next drive

Загрузить только новые изображения; не повторять успешно собранные.

Что попадает в комплект

photo_prompt_pack/
├── photo_01.png
├── photo_01.md ← промпт для новой модели
├── photo_01.json ← сцена, теги, камера
├── _index.json
├── _collection_state.json
└── README.md

MD-промпт описывает позу, одежду, освещение, камеру и окружение так, чтобы сцену можно было повторить с внешностью человека из нового референса. JSON отражает видимый результат изображения, а не предположения по исходному запросу.

✓
При next учёт идёт по подтверждённым исходным ID и контрольным суммам. Если старый архив недоступен, GP не должен объявлять повторы исключёнными без проверки.

02 / сохранение

Drive. Нужное — в нужную папку.

Сохранение результата текущей задачи на подключённый Google Drive. Не путать с командой VNS: обычный drive не собирает историю чата или все изображения автоматически.

@gp drive

Папка с текущей датой: gp/MMDD.

@gp drive s/2025

Точный путь: gp/s/2025.

@gp drive vns cur

Подпапка с датой: gp/vns/MMDD.

@gp drive vns cur+

Первый свободный номер: gp/vns/MMDD-1, -2…

Как выбрать папку

gp/→ваш подпуть→cur или cur+

cur использует папку с датой формата MMDD повторно. cur+ создаёт новую папку MMDD-N, где N — первый незанятый номер. Существующие файлы не должны перезаписываться без явной команды.

@gp drive vns cur+

03 / история и вложения

Журнал чата. Не терять контекст.

Три семейства команд на разную глубину экспорта: файлы, переписка с событиями или только текст. Для журнала формируется скачиваемый ZIP.

Все доступные файлы

@gp drive-all

Доступные файлы пользователя и GPT.

@gp drive-all-gpt

Только файлы, созданные или прикреплённые GPT.

Журнал с ZIP

@gp drive-log

Тексты, файлы, видимые логи, ошибки и предупреждения обеих сторон.

@gp drive-log-gpt

Доступные сообщения и результаты GPT.

@gp drive-log-my

Ваши сообщения и доступные вложения.

drive-log.zip
├── conversation.md
├── messages/
├── events/
├── files/
├── _index.json · MANIFEST.json
├── checksums.sha256
├── MISSING.md
└── README.md

Текстовые сообщения и файлы имеют последовательные имена N-DDMM-краткая-тема. Внутри текстовых файлов — доступный полный текст, не краткое резюме. После создания ZIP команда дополнительно пытается сохранить его в Drive.

Только текст

@gp drive-txt

Тексты ответов GPT, без файлов.

@gp drive-txt-all

Тексты обеих сторон, без файлов.

@gp drive-txt-my

Только ваши текстовые сообщения.

!
Граница возможностей. У GP нет скрытого API всей переписки. Экспортируется только то, к чему действительно есть доступ: сообщения, видимые записи работы и байты файлов. Скрытые рассуждения модели, внутренние системные журналы и недоступные изображения в архив не попадут. Пропуски перечисляются в MISSING.md.

04 / Google Документы

Docs. Исследование отдельной вкладкой.

Один Google Документ — несколько редактируемых вкладок. Добавляйте исследование из чата, приложенный PDF/DOCX или оба источника. Это не публикация на GitHub Pages.

@gp doc tab @nws

Текущий результат — новой вкладкой Google Docs.

@gp doc tab @nws "Deep Research"

Назвать вкладку Deep Research.

@gp doc tab @nws "Исходный документ" file

Содержимое приложенного PDF/DOCX — в новую вкладку.

@gp doc tab @nws "Все материалы" all

Текущий ответ и относящиеся к нему вложения.

В какой документ?

Вместо @nws допускается ссылка Google Docs или ID. @nws — пример упоминания: GP должен найти именно выбранный документ, а не угадывать его по названию.

Google Документ · вкладки
├── Обзор
├── Хронология
├── Deep Research  ← новая вкладка
└── Исходный документ

Режимы содержимого

current — текущий результат или Deep Research (по умолчанию); file — приложенный файл; all — оба источника с отдельными заголовками.

✓
Перед записью GP проверяет документ и его вкладки. Новая вкладка не изменяет прежние. Для обычного DOCX требуется создать нативную копию Google Docs — исходный файл нельзя преобразовать без отдельного разрешения.

04 / публикация

IO. Из ответа — в работающую страницу.

GP создаёт статическую HTML-страницу из текущего результата, публикует её в публичном репозитории greenn/gp и возвращает адрес GitHub Pages.

@gp io

Публикация текущего материала в s/<english-kebab-slug>/.

@gp io ds

Интерактивная HTML-версия исследования в ds/<slug>/.

@gp io ds ?url

То же: ?url необязателен, ссылка выдаётся всегда.

Как выглядит путь

https://greenn.github.io/gp/ds/ai-tools-for-teachers/

Папка получает короткое понятное английское название. Внутри — index.html и доступные исходные материалы. Запись также появляется в главном каталоге сайта. Для исследований могут быть добавлены поиск, оглавление и фильтры, если они полезны по содержанию.

↗
Публикация через io общедоступна. Не переносите туда пароли, личные данные или закрытые файлы. Drive и IO — разные места сохранения.

05 / адресное обновление

UPD. Обновить страницу по короткому ключу.

Не нужно вводить полный URL. GP ищет уже опубликованную страницу в greenn/gp по точному пути, фрагменту названия или ключевым словам. После проверки цели изменяет её на прежнем адресе.

@gp upd plg-t2f

Найти справочник T2F в man/plg-t2f/ и обновить его содержимое по текущему запросу.

@gp upd man/plg-gp

Явно указать уже существующую подпапку страницы.

@gp upd plg-t2f добавь раздел частых команд

Ключ страницы и задача в одной команде.

@gp upd https://greenn.github.io/gp/man/plg-t2f/

Полный точный URL также поддерживается, только в границах публикаций greenn/gp.

Как выбирается страница

Ключ: plg-t2f→Поиск существующего каталога→Сверка совпадения→Правка и проверка

Приоритет совпадений: точный URL или путь, точное имя каталога, уникальная часть пути, затем название страницы и ключевые слова. Если кандидатов несколько и однозначного победителя нет — GP показывает варианты и не редактирует ничего до выбора. Если ничего не найдено — новую страницу автоматически не создаёт.

✓
Сохраняются URL и существующий UI: работающие разделы, адаптивность, поиск, JS и копирование команд. Сторонние файлы не перезаписываются, старые страницы не удаляются. Права записи и успешный коммит проверяются отдельно.

07 / полезно знать

Частые вопросы.

Коротко об ограничениях и ситуациях, которые легко перепутать.

Можно ли добавить PDF в существующий Google Документ?

Да: @gp doc tab @nws "Исходный документ" file. Содержимое извлекается и добавляется в новую вкладку нативного Google Docs; старые вкладки сохраняются.

Где хранятся результаты GP?

vns без drive создаёт ZIP для скачивания. drive* отправляет результаты в Google Drive и в режиме drive-log* также даёт ZIP в чате. io публикует страницу в открытом GitHub-репозитории.

Может ли vns next гарантировать отсутствие повторов?

Только если есть доступные прошлые архивы или проверяемые идентификаторы/хеши результатов. Недоступные генерации не следует считать обработанными.

Почему в drive-log могут отсутствовать сообщения?

GP не получает полный системный экспорт чата и не может прочитать скрытые служебные данные. Файлы, для которых нет исходных байтов, и обрезанная история фиксируются как пропуски.

Зачем cur+ вместо cur?

cur повторно использует календарную папку, например gp/vns/1015. cur+ ищет первую свободную номерную папку, например gp/vns/1015-2. Это снижает риск смешать отдельные выгрузки.

Что означает ?url у io?

Это необязательный сигнал «покажи ссылку». URL формируется автоматически после записи публикации в репозиторий даже без этого параметра. Работу GitHub Pages после коммита нужно отдельно проверять.

Как обновить существующую страницу, не зная полного названия?

Введите @gp upd plg-t2f и опишите изменения. GP найдёт кандидата по ключу в репозитории. При неоднозначности попросит выбрать страницу. Старый URL сохранится.

GP работает автоматически между сообщениями?

Нет. Он выполняет команды при вызове в чате и зависит от подключённых инструментов. Фоновое копирование или доступ ко всем сообщениям из других чатов не подразумевается.
